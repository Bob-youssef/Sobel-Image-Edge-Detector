Hardware/Software Co-Design Pipeline

Because FPGAs operate on raw binary signals, they cannot natively read complex file formats like .jpg. We designed a 3-stage automated pipeline to test our hardware:

1. Python Pre-Processing

A script converts the input image to grayscale, resizes it to 256x256 to limit simulation time, and dumps all 65,536 pixels into a Hexadecimal text file.

➡️

2. Verilog Simulation

ModelSim uses $readmemh to stream the hex file into our custom Top-Level module at 1 pixel per clock cycle, simulating a real-time camera feed.

➡️

3. Python Rebuilding

The hardware flags valid edges and saves them via $fwrite. A final Python script reconstructs the 2D grid into the final edge-detected image.

The Architecture: The Line Buffer

The Challenge: Pixels arrive in a single-file stream. Sobel math requires a 3x3 kernel. How do we look at 3 rows simultaneously?

The Solution: We instantiate dual-port Block RAMs as 256-pixel Conveyor Belts to force the data to stack vertically. This creates a perfect sliding 3x3 D-Flip-Flop grid.

The Architecture: Sobel Math Module

The module applies the Gx and Gy Convolution Matrices to the 3x3 grid to find the gradient magnitude.

// 1. Zero-extend the 8-bit unsigned pixels to 9-bit signed numbers to allow negative subtraction
wire signed [8:0] s11 = {1'b0, p11};

// 2. Hardware Optimization: We replace expensive Multipliers with Bit-Shifting (<<< 1)
wire signed [11:0] gx = (s13 + (s23 <<< 1) + s33) - (s11 + (s21 <<< 1) + s31);

// 3. Combinational Thresholding
wire [7:0] edge_pixel = (abs_gx + abs_gy > THRESHOLD) ? 8'hFF : 8'h00;

System Integration & Verification

To verify the design, we used ModelSim to execute our Master Testbench.

Timing Constraints

The window_valid signal requires exactly 515 clock cycles to trigger. This accounts for filling both 256-pixel RAM belts, plus the 3 additional clock cycles required to shift the data across the 3x3 grid.

File I/O Verification

Because the hardware discards the first 515 cycles, our output text file contains exactly 65,021 valid pixels. Our Python reconstruction script automatically detects this offset and zero-pads the borders, successfully reconstructing the perfect edge-detected image!
